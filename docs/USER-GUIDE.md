# 日常使用指南

Agent Workspace Manager（AWM）用于把一个研发任务准备成明确、可追溯的本地 Agent 工作区。它管理任务、服务工作区、Git 风险状态、`AGENTS.md` 和当前唯一的交付动作：UAT Tag。

## 适用场景

- 一个需求需要同时修改多个服务；
- 研发使用 IDEA、WebStorm、Codex 或 Cursor 在本地开发；
- 需求来自飞书，团队按组（业务线）管理服务；
- 提交测试环境前需要创建可追溯的 UAT Tag。

AWM 隔离的是代码工作目录和 Git 工作区；端口、数据库、Docker、凭据和外部测试环境仍由项目本身管理。

## 首次设置

1. 在“设置”中选择任务根目录。每个任务会在该目录下创建一个子目录。
2. 使用“添加仓库”选择本地 Git 主仓库。可多选目录；非 Git、Bare 仓库、临时 Linked Worktree 和重复仓库会被跳过。
3. 在组中添加服务并设置显示名称、基础分支、工作区策略及需要时的 UAT Tag 规则。
4. 可选：填写 IDE、终端和任务完成后默认打开的工作区工具。
5. 可选：在高级设置中填写飞书 Meegle 的 `project_key` 和 `simple_name`。创建任务时会查询已配置空间中属于当前登录用户的进行中 Sprint 需求。

未创建额外组时，应用保留一个默认组，并在任务与服务页面隐藏组层级。

## 创建研发任务

1. 点击“创建研发任务”。
2. 手工填写飞书需求链接，或从候选需求中选择。Meegle 可用时会尝试填写任务名称。
3. 填写“任务名称 / 文件夹名称”。它会原样成为任务目录名，不能包含 Windows 非法字符、保留设备名、末尾点或空白。
4. 确认任务分支。组的默认前缀可包含 `{num}`；它会从需求链接或普通文本中的最后一段数字解析。
5. 选择本任务需要修改的服务。服务搜索只过滤展示，不会清除已选服务。
6. 在右侧填写任务人工说明，或预览最终 `AGENTS.md`。选择工作区工具后点击创建。

创建期间可以继续查看任务和复制信息；只有会与当前 Git 或配置写入冲突的动作会被禁用。

## 服务与工作区策略

### 标准 Worktree

适用于需要为任务创建独立 Feature 分支的服务。创建时会从最新已获取的基础远程引用创建 Worktree，不会切换或移动主 checkout。不同基础分支创建不同 Worktree；相同基础分支共用同一个物理 Worktree。

### 独立克隆

适用于需要直接在固定远程分支工作的服务。它从 `origin` 完整克隆并检出选定分支，不额外创建 Feature 分支、Worktree 或执行 Bootstrap。多个任务同时使用同一远程分支时仍可能产生业务层面的代码冲突，团队需要自行协调。

## 任务详情与 Git 状态

每个工作区显示：

- `无未提交` 或 `N 个文件未提交`：包含 staged、unstaged、冲突和未跟踪文件，不包含 ignored 文件；
- `已推送` 或 `N 个提交未推送`：只比较本地已知 upstream，不执行 fetch；
- `检查中`、`检查失败` 或 `工作区不存在`：需要修复后再继续。

任务详情可复制分支和路径、打开 IDE/终端/文件夹、查看工作数据、添加服务，以及在满足开关条件时构建 UAT Tag。

## AGENTS.md

说明分为三层：

```text
~/.AgentWorkspaceManager/agents/global/AGENTS.md
~/.AgentWorkspaceManager/agents/groups/<groupId>/AGENTS.md
<任务目录>/AGENTS.md
```

设置页可直接编辑全局或组说明，也可以在对应文件路径用外部编辑器修改。任务级文件保留人工说明区；保存任务说明时，系统区会按最新任务、全局说明和组说明重新生成。外部编辑与未保存本地编辑冲突时，必须选择磁盘版本或本地版本。

## UAT Tag 与归档

UAT Tag 只在组开关和服务模块/独立克隆子开关都开启时可用。构建前会执行 Git 风险检查和临时合并预检；不会 Force Push、自动 Rebase 或自动解决冲突。详细规则见 [安全与 UAT Tag 流程](SAFETY-AND-TAG-FLOW.md)。

归档或删除前会检查未提交内容、未推送提交和进行中的 Git 操作。强制归档可能丢弃未保存文件，只应在确认风险后使用。
